Verdict: Passed locally

- `NotificationPipeline` interface and `DefaultNotificationPipeline` wire notification snapshots from `NotificationIngress` through parsing, deduplication, DataStore settings resolution with bounded wait, reading policy evaluation, and speech request emission.
- Bounded capacity and overflow semantics:
  - Speech requests flow through a bounded channel (`capacity = 64`, `DROP_OLDEST`) ensuring no unbounded memory growth.
  - Diagnostics flow through a bounded shared flow (`extraBufferCapacity = 128`, `DROP_OLDEST`, `replay = 64`).
  - Settings retrieval is bounded by a 2000ms timeout failing closed (`SettingsUnavailable`) without throwing or stalling the pipeline.
- Privacy & Redaction compliance (ADR-009):
  - `PipelineDiagnostic` emits structured data classes with coarse enums (`DiagnosticOutcome`, `DiagnosticParserOutcome`, `ConversationType`, `ParseSource`).
  - Emits process-salted, one-way truncated correlation tokens (8 hex characters) via `DiagnosticCorrelation` with an ephemeral UUID salt.
  - No message bodies, sender display names, group titles, or raw IDs (`ConversationId`, notification key, shortcut ID) ever appear in diagnostic payloads or `toString()`.
- Fake ingress end-to-end unit tests (`NotificationPipelineTest`):

  - Covers all skip paths: `SkipReaderDisabled`, `SkipRidingModeInactive`, `SkipPrivateDisabled`, `SkipGroupNotSelected`, `SkipRedacted`, `SkipUnsupported` (summary, call, attachment), `SkipTooOld`.
  - Covers duplicate suppression before policy evaluation (`DuplicateSuppressed`), including partial duplicate bursts.
  - Covers settings timeout fail-closed behavior (`SettingsUnavailable`).
  - Verifies ADR-009 redaction invariants across all emitted diagnostics.
