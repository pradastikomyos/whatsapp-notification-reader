## Delivered

- `ObservedConversationsRoute` observes the Room group catalogue and DataStore
  settings. It never fabricates groups or directly owns service lifecycle.
- The current `ALL_OBSERVED_GROUPS`, `SELECTED_GROUPS_ONLY`, or `NO_GROUPS`
  policy is visible even when the catalogue is empty.
- Selection switches are actionable only under `SELECTED_GROUPS_ONLY`. An
  explicit toggle first updates `AppSettings.selectedConversationIds`, the
  effective policy source observed by the pipeline, then synchronizes Room's
  catalogue selection metadata.
- New discovery cannot select a group: the UI derives selected state from
  DataStore, whose set is unchanged by repository observation.
- Selection write failures are reported without optimistic state changes or UI
  coroutine crashes. DataStore remains authoritative; a later Room metadata
  synchronization failure is best-effort and never rolls back effective policy.
- Cancellation remains propagated through both storage operations.
- Duplicate display names remain separate rows, WhatsApp and WhatsApp Business
  sources are differentiated, and ADR-004 fallback collision flags are visible.

## Navigation Handoff

The navigation/shared-UI owner must expose `ObservedConversationsRoute` with
`AppContainer.settingsRepository` and `AppContainer.conversationRepository`.
This task deliberately does not modify `MainActivity` while P5 screens are
being implemented in parallel.
